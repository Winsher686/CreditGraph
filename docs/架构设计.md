# 架构设计

## 1. 分层（洋葱 / 六边形）

依赖只朝内：`interfaces → application → domain`，`infrastructure` 实现 `application/ports.py`
里的 Protocol 供上层倒置注入。

| 层 | 目录 | 允许依赖 | 关键内容 |
| --- | --- | --- | --- |
| 领域 | `domain/` | 仅标准库 | `credit.py`（规则引擎 + 审批矩阵 + 风险/决策枚举）、`retrieval.py`（切块 + RRF）、`guardrails.py` |
| 应用 | `application/` | 领域 + 端口 | `graph.py`（状态图）、`routing.py`（角色与工具权限）、`tools.py`、`credit_rules.py`、`credit_service.py`、`material_analysis.py` |
| 基础设施 | `infrastructure/` | 应用 / 领域 | `credit_repository.py`（6 张表）、`knowledge.py`（FTS5 + 向量 + RRF）、`llm.py`、`embeddings.py` |
| 接口 | `interfaces/` | 全部 | `api.py`（FastAPI + SSE，组合根）、`cli.py`、`demo.py` |

> 为什么图不写数据库：`AsyncSqliteSaver` 检查点与业务表共用同一个 SQLite 文件，节点内同步写会
> 拖住检查点连接（表现为 `database is locked`）。因此图保持纯函数式，接口层在 `done` 时调用
> `CreditService.persist_run` 统一落库。

## 2. 审批状态图

📄 **[审批状态图（PDF）](../docs/assets/approval-state.pdf)** — `approval_route` 按 `auto / manual` 分流：
自动档直达 `final_decision`，人工档进入 `human_approval`（可 `escalate` 回环重新中断），
审批意见经 `merge_opinion` 回流到最终决策。

> 图源由 `scripts/generate_diagrams.py` 生成。

| 节点 | 职责 | 是否调用模型 |
| --- | --- | --- |
| `intake` | 材料接收与解析 → 结构化字段 + 缺失清单 | 否（确定性） |
| `risk_assessment` | 检索政策依据（RAG）→ 生成风险评估报告，解析失败回退 `heuristic_risk` | 是（large 档） |
| `rule_engine` | 自动拒绝 / 合规 / 自动通过 / 转人工 | 否 |
| `approval_route` | 审批矩阵 → 审批层级与是否可自动终局 | 否 |
| `human_approval` | **HITL 中断点**（`interrupt()`），等待审批动作 | 否 |
| `escalate` | 审批层级升级（初级 → 高级 → 合规）后重新中断 | 否 |
| `merge_opinion` | 合并审批人意见/修改，生成最终结论 | 是（standard 档） |
| `final_decision` | 汇总终局决策并生成审批链终结点 | 否 |

## 3. 状态模型（CreditState）

`application_id` / `operator_id` / `applicant` / `loan` / `materials` / `parsed_material` /
`policy_libraries` / `risk_assessment` / `risk_level` / `citations` / `rule_result` /
`route_level` / `route_reason` / `pending_opinion` / `approval_chain` / `approval_records` /
`decision` / `decision_reason` / `final_conclusion` / `review_type` / `stage` / `tool_rounds`。

`messages` 使用 `add_messages` 归约器（追加），其余键为覆盖语义。

## 4. 规则引擎与审批矩阵

规则优先级：**自动拒绝 > 合规拦截 > 自动通过 > 转人工**。任一条自动拒绝命中即终局拒绝，
避免「黑名单客户被自动放款」；合规命中优先于自动通过，避免「可疑资金走自动通道」。

审批矩阵：

| 条件 | 层级 |
| --- | --- |
| 低风险 且 金额 < 10 万 | `auto` 自动通过 |
| 中风险 且 10–50 万 | `junior` 初级审批人 |
| 高风险 或 金额 > 50 万 | `senior` 高级审批人 |
| 反洗钱 / 关联交易 / 受限行业 | `compliance` 合规部门 |

阈值由 `CreditRules` 注入（`.env` / `CREDITGRAPH_RULES_JSON` 覆盖），领域层是纯函数，改配置不改代码。

## 5. HITL 中断与恢复

1. 图执行到 `human_approval`，节点内调用 `interrupt(payload)`，抛出 `GraphInterrupt`，图暂停。
2. `AsyncSqliteSaver` 把当前状态写入检查点；SSE 推送 `interrupt` 事件（含报告、路由信息、可选动作）。
3. 审批人调用 `/approve|/reject|/modify|/escalate`（内部 `Command(resume=opinion)`）。
4. 图从**同一 `thread_id`** 恢复，`interrupt()` 返回该意见对象；若动作为 `escalate`，走 `escalate`
   节点升级后**再次中断**；否则进入 `merge_opinion` → `final_decision`。
5. 断开进程不丢状态——重启后凭 `thread_id` 继续。复审使用独立 `thread_id`（`app-{id}-recheck-{ts}`）
   以保证从干净状态重跑。

## 6. 知识库与检索

- 三张检索索引：`chunks`、`chunks_fts`（FTS5 `trigram` 分词，适配中文）、`chunk_vectors`（向量 blob）。
- 查询：FTS5 OR 查询串 + 向量余弦，两路结果用 RRF（`1/(k+rank)`）融合，短查询回退 `LIKE`。
- 政策库分类：信贷政策 / 审批规则 / 风险案例 / 监管要求 / 反洗钱规则；检索结果带出处（库 + 标题 + 片段），
  注入风险报告与提示词。

## 7. 关键取舍

- **Mock 优先**：确定性 Mock 覆盖三档风险 + 合规 + HITL，全部测试零 API 消耗。
- **图纯化**：DB 写集中在接口层，规避检查点锁竞争。
- **确定性回退**：模型输出不可解析时用 `heuristic_risk` 兜底，审批流程不因模型异常而卡死。
- **升级即重中断**：升级不自动放行，必须由更高级审批人显式决策。
