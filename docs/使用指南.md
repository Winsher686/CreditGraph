# 使用指南

## 环境要求

- Python 3.12+ 与 [uv](https://docs.astral.sh/uv/)
- Node.js 20+（仅前端界面需要）

## 安装

```bash
uv sync                          # 后端依赖
cd frontend && npm install && cd ..   # 前端依赖（首次）
```

默认使用**确定性 Mock 模型**，零 API 消耗，可直接体验完整审批流程。

## 播种示例数据

```bash
uv run creditgraph-demo --reset
```

写入 5 个政策知识库（信贷政策 / 审批规则 / 风险案例 / 监管要求 / 反洗钱规则）与 4 笔示例申请：

| 申请 | 场景 | 预期走向 |
| --- | --- | --- |
| #1 张小雨 · 6 万 | 低风险小额 | 自动通过 |
| #2 李建国 · 30 万 | 中风险中额 | 初级审批人 |
| #3 王强 · 250 万 | 大额 + 现金周转 + 关联交易 | 合规部门 |
| #4 赵敏 · 10 万 | 征信黑名单 | 自动拒绝 |

> `--reset` 会清空并重建数据库；如需保留先备份 `data/creditgraph.db`。

## 命令行体验

```bash
# 查看审批矩阵与阈值
uv run creditgraph rules

# 提交一笔申请并跑完整工作流
uv run creditgraph new --name 李建国 --income 18000 --debt 9000 --score 660 \
    --amount 300000 --term 36 --purpose 店面装修

# 输出会依次打印：材料接收 → 风险评估报告（含政策依据）→ 规则引擎 → 审批路由，
# 然后在 [HITL 中断] 处询问审批动作：approve / reject / modify / escalate
```

`--auto` 可自动同意所有审批动作（仅用于演示）。

## Web 界面

```bash
./scripts/dev.sh        # 后端 8011 + 前端 3000
```

打开 <http://localhost:3000>：

1. **审批总览**：点「＋ 新建申请」填写申请人 / 贷款信息提交；下方是申请列表。
2. **审批台**（点列表里的「进入审批台」）：
   - 「▶ 运行审批工作流」→ 实时看到节点进展与 AI 风险评估报告；
   - 若触发人工审批，页面出现**审批操作区**：选审批人、填意见，可「通过 / 拒绝 / 修改风险评估后提交 / 升级」；
   - 下方面板展示 AI 风险评估报告与**审批链 / 审计日志**；
   - 已通过的贷款可点「发起贷后复审」。
3. **政策知识库**：查看 / 新增政策、规则、案例文档（风险评估的依据来源）。
4. **规则与审批矩阵**：查看当前阈值与矩阵。

## 自定义审批规则

改 `.env`（或环境变量）即可，无需改代码：

```bash
CREDITGRAPH_AUTO_APPROVE_MAX_AMOUNT=80000     # 自动通过金额上限
CREDITGRAPH_SENIOR_REVIEW_MIN_AMOUNT=300000   # 高级审批金额下限
CREDITGRAPH_AML_AMOUNT_THRESHOLD=1000000      # 反洗钱上报金额
CREDITGRAPH_MAX_DTI=0.65                      # 负债率上限
CREDITGRAPH_MIN_MONTHLY_INCOME=4000           # 最低月收入
CREDITGRAPH_MIN_CREDIT_SCORE=620              # 自动通过最低评分
CREDITGRAPH_APPROVAL_TIMEOUT_MINUTES=60       # 审批超时
```

更细的规则（受限行业、可疑用途等）用 JSON 覆盖：

```bash
CREDITGRAPH_RULES_JSON={"max_dti":0.6,"restricted_industries":["虚拟货币","博彩"],"aml_purposes":["现金周转"]}
```

## 接入真实模型

```bash
uv sync --extra openai

```

## 常见问题

**Q：为什么运行 `uv run pytest` 报 PermissionError？**
沙箱环境下需要指定 basetemp：`uv run pytest -q --basetemp=.pytest-tmp`。

**Q：审批中断后关掉进程，状态会丢吗？**
不会。`AsyncSqliteSaver` 把中断状态写进 `data/creditgraph.db` 的检查点，凭 `thread_id`（`app-{id}`）恢复。

**Q：数据库在哪？**
`data/creditgraph.db`（可用 `CREDITGRAPH_DATABASE_PATH` 覆盖），包含业务表、政策知识库与检查点。

**Q：Mock 模式能测什么？**
覆盖三档风险、自动通过 / 自动拒绝 / 合规、HITL 四类审批动作、升级与复审的完整链路——全部断言零 API 消耗。
